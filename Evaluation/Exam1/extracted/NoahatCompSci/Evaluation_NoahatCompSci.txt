Question 1

Part 1:
Fuel efficiency is a calculated value and should not be stored as a directly settable field. Providing a setter allows invalid or arbitrary values to be assigned. Instead, implement a getFuelEfficiency() method that computes and returns the value using the appropriate formula.

In the Van and Truck classes, setRating is being called in the constructor while fuel efficiency is also computed in calculateFuelEfficiency(). This duplicates work. The setter should be removed, and fuel efficiency should be derived only through calculateFuelEfficiency().

Part 4:
VehicleDemo does not extend Vehicle; it uses it. This relationship should be represented in UML as a weak association/dependency link with an open arrow, not as an inheritance relationship.
